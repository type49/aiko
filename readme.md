
## Что это

Айко —  это модульная экосистема персонального ассистента под Windows, работающая по принципу **Edge Computing**. Платформа предоставляет готовое ядро обработки команд, мультиканальный ввод/вывод и plugin-систему с нулевым boilerplate.

Разработчик пишет один класс — платформа сама занимается маршрутизацией, активацией, UI и персистентностью.

---

## Архитектура

Система строится вокруг трёх слоёв.

### Слой ввода

Обрабатывает три независимых источника команд:

|Источник|Реализация|Описание|
|---|---|---|
|Микрофон|Vosk, STT оффлайн, 16кГц|Голосовые команды без облака|
|Telegram|aiogram, webhook-мост|Те же команды через мессенджер|
|GUI|PySide6|Прямые вызовы из интерфейса|

Все три источника регистрируются через `ctx.set_input_source()` и проходят через единый роутер. Плагин не знает, откуда пришла команда — он получает только текст и `ctx`.

### Слой ядра

`AikoCore` управляет жизненным циклом подсистем через threading с `stop_event`, реализует Hardware Watchdog для аудиопотока (детектирует захват микрофона другим приложением и перезапускается), и пробрасывает все зависимости через dependency injection, избегая циклических импортов.

### Слой контекста

`AikoContext` — центральная state-машина с `threading.Lock`. Все изменения состояния (микрофон, UI-статус, режимы) проходят через неё с валидацией типов и автоматическим откатом к предыдущему состоянию. Контекст уведомляет GUI через Qt-сигналы (`state_changed.emit`) и доступен из любого места через глобальный реестр:

```python
from global_context import ctx

ctx().broadcast("Привет из любого места")
```

## Pipeline обработки команды

```
Аудиопоток (sounddevice)
  → STT (Vosk)
    → ActivationService (имя-триггер + активное окно с таймаутом)
      → CommandRouter
          → NLU (двухуровневый: Keyword O(1) → LinearSVC + TF-IDF)
          → FuzzyMatcher (rapidfuzz, настраиваемый порог)
          → Fallbacks
            → plugin.execute(text, ctx)
              → ctx.reply() / ctx.broadcast()
```

---

## NLU-слой

Двухуровневый классификатор команд.

**Уровень 1 — Keyword matching** (быстрый, O(1)): точный поиск по словарю триггеров из плагинов. Проверяет первые 3 слова и вхождение триггера в любом месте фразы.

**Уровень 2 — ML-модель** (умный): пайплайн `TfidfVectorizer + LinearSVC`, который обучается на `samples` из плагинов при старте. Модель кешируется по MD5-хэшу тренировочных данных и перестраивается только при изменении плагинов.

```python
# config.json
{
  "nlu": {
    "threshold": 0.6   # порог уверенности ML-модели
  }
}
```

Если ни один уровень не сработал — запрос уходит в fallback-цепочку.

## Plugin System

### Создание плагина

Плагин — это Python-класс, наследующий `AikoCommand`:

```python
from interfaces import AikoCommand

class MyPlugin(AikoCommand):
    # Ключевые слова для быстрого роутинга
    triggers = ["сделай", "выполни"]

    # Примеры фраз для обучения ML-модели
    samples = [
        "можешь сделать это",
        "выполни задачу",
        "сделай что-нибудь",
    ]

    def execute(self, text: str, ctx) -> bool:
        # True = команда принята и выполнена
        # False = не наш случай, роутер попробует следующий плагин
        ctx.reply("Готово")
        return True

    def on_tick(self, ctx):
        # Опционально: вызывается планировщиком каждые N секунд
        pass
```

Положите файл в директорию `plugins/` — и он будет подхвачен при следующем запуске. Ошибка в одном плагине не мешает загрузке остальных.

### Структура плагинов

Поддерживаются два формата:

```
plugins/
├── my_simple_plugin.py          # одиночный файл
└── my_complex_plugin/           # папка-пакет
    ├── __init__.py
    └── my_complex_plugin.py     # основной модуль
```

### API контекста внутри плагина

```python
def execute(self, text: str, ctx) -> bool:
    # Ответить туда, откуда пришла команда (mic / tg / gui)
    ctx.reply("Ответ")

    # Вещать во все каналы сразу
    ctx.broadcast("Сообщение", ui=True, tg=True)

    # Показать уведомление с уровнем
    ctx.ui_output("Что-то случилось", level="error")

    # Открыть окно
    ctx.open_ui("chat_window")

    # Глобальное состояние
    ctx.microphone_enabled
    ctx.focus_mode_active
    ctx.last_input_source   # "mic" | "tg" | "gui"

    return True
```

## Мультиканальный вывод

`ctx.reply()` смотрит на `last_input_source` и автоматически отвечает в нужный канал. `ctx.broadcast()` позволяет явно указать каналы.

```python
# Умный ответ: туда, откуда пришёл запрос
ctx.reply("Готово")

# Явное управление каналами
ctx.broadcast("Оптимизация завершена", ui=True, tg=True)
ctx.broadcast("Только в UI", ui=True, tg=False)
```

Это означает: один плагин без изменений работает из голоса, из Telegram и из GUI-кнопки.

## Надёжность

- **Watchdog-потоки** — `MAX_RESTARTS = 3`, `RESTART_COOLDOWN = 5s`. Упавший поток перезапускается автоматически.
- **Hardware Watchdog** — детектирует захват микрофона другим приложением по таймауту тишины и пересоздаёт поток.
- **AppLifecycle** — lock-файл с PID. При следующем запуске система детектирует аварийное завершение предыдущей сессии.
- **Thread-safe контекст** — весь state-management защищён `threading.Lock` с валидацией типов.
- **UI State Machine** — статусы `init → idle → active → blocked → mute` образуют конечный автомат с защитой от невалидных переходов и автоматическим восстановлением предыдущего состояния.
- **Изолированная загрузка плагинов** — каждый плагин добавляется в `sys.path` независимо; ошибка парсинга одного не блокирует остальные.
